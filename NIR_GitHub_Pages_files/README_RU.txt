НИР: автономный браузерный эксперимент, тестовый пакет Android PWA
27.10.2026

СТАТУС
Python действительно выполняется в WebAssembly внутри Web Worker браузера.
Расчётный сервер не используется. Это отдельная opt-in версия; Windows не заменяется.
Локальная desktop-проверка не подтверждает работу настоящего телефона.
Публичное размещение не выполнено: разрешённого стабильного HTTPS-адреса пока нет.
ZIP нельзя просто открыть на Android через file:// и считать установленной PWA.

ПЕРВАЯ УСТАНОВКА
1. Разместить содержимое android-pwa на согласованном статическом HTTPS-хостинге,
   сохранив относительные пути. Не добавлять серверные расчётные API.
   MIME: .wasm application/wasm; .js text/javascript; .json application/json;
   .webmanifest application/manifest+json; .zip/.whl application/octet-stream.
   Не заменять отсутствующие файлы HTML-страницей. Все ресурсы из asset-manifest.json
   должны отдаваться без авторизационных перенаправлений. Scope — папка приложения.
2. Открыть HTTPS-адрес в Chrome Android при работающем интернете.
3. Дождаться «Готово к работе без интернета»: проверяются SHA-256 всех ресурсов,
   запускаются Pyodide, NumPy и настоящий короткий физический расчёт.
4. Через меню Chrome выбрать штатное добавление/установку на главный экран.
   Не отключать защиту Chrome, не обходить предупреждения сертификата.
5. Закрыть все вкладки приложения, открыть снова. Хранение зависит от браузера:
   очистка данных/нехватка места может удалить ресурсы и историю.

КАК РАБОТАТЬ
По умолчанию — интерактивный опыт 60 с, Fixed ECMS, synthetic АКБ 100 А·ч.
«Начать новый опыт» создаёт новую историю. Прежняя остаётся в IndexedDB.
«Один шаг» считает одну модельную секунду, не обязательно за одну реальную секунду.
«Запуск» выполняет шаги последовательно. Пауза/стоп применяются на границе шага.
Пока считается новый шаг, показатели подписаны как предыдущий принятый результат.
Ввод нагрузки/воздуха — черновик. «Применить» ставит команду на начало следующего
шага; квитанция и вертикальная отметка показывают фактическое время применения.
Fixed ECMS выбирает из 5000/5750/6500 rpm. Ручной режим задаёт желаемую ближайшую
допустимую точку из того же набора, не жёсткое физическое управление валом.
Профиль 60 с — 20 с по 6, 5 и 7 кВт; в нём интерактивные воздействия недоступны.

ДАННЫЕ И ФИЗИЧЕСКИЕ ОГРАНИЧЕНИЯ
Сохранены исходные Python-модели, допуски и физический шаг 1 с.
Температурный feedback работает; электрические температурные коэффициенты АКБ
выключены. Manufacturer charge policy не подключена, legacy-запрет заряда при
T<0 сохранён. Aging/plating не подключены. Нагрузка в кВт, расчёта массы нет.
Исходные допущения synthetic/analogue не становятся паспортными характеристиками.
Расчёт при открытом приложении на переднем плане; при скрытии запрашивается пауза.
Android может принудительно завершить процесс — гарантии фонового расчёта нет.

СОХРАНЕНИЕ И REPLAY
После каждого принятого шага checkpoint записывается в IndexedDB до следующего.
При повторном открытии показывается сохранённый префикс только для просмотра;
точное продолжение скрытого состояния контроллера после аварии не обещается.
Эксперимент JSON сохраняет config, snapshot профилей, идентичность моделей,
события, состояние и результаты. CSV — таблица, SVG — график мощности.
Формат JSON этой версии отдельный: nir.android.experiment/schema_version=1;
Windows JSON автоматически не конвертируется и явно отклоняется.
«Открыть JSON» → выбрать файл → «Выполнить свежий replay»:
новая сессия пересчитывается от начального состояния до сохранённой границы.
Старые значения не используются вместо физических вычислений.
При несовпадении моделей/профилей replay запрещён с объяснением.
Список сохранённых опытов открывает историю; не возобновляет контроллер.
«Ограничения и диагностика» → «Сохранить диагностику» — JSON со средой,
версиями, измерениями, cache proof и текущим принятым отчётом.

ОБНОВЛЕНИЕ
Новый ресурсный набор готовится в отдельном кэше. Неудачная загрузка не удаляет
старый набор. Нет принудительного skipWaiting в середине опыта. Если появилось
уведомление об обновлении, остановить опыт, сохранить JSON, закрыть ВСЕ вкладки
приложения и открыть снова. Старые кэши автоматически не удаляются этой версией.

ПРИЁМКА НА НАСТОЯЩЕМ ANDROID — ОСТАЁТСЯ НЕПОДТВЕРЖДЁННОЙ
Активные действия займут около 5–10 минут плюс ожидание вычислений телефона.
Записать: телефон ______ Android ______ Chrome ______ дата ______ HTTPS ______.
1. Подготовить/установить по инструкции выше, сохранить диагностику «до».
2. Закрыть Chrome/PWA, выключить компьютер и все локальные расчётные процессы.
3. Включить авиарежим. ОТДЕЛЬНО выключить Wi-Fi и мобильные данные.
4. Со значка открыть приложение заново, дождаться готовности ядра из кэша.
5. Создать НОВЫЙ опыт 6 с: нагрузка 6,4 кВт, воздух 15 °C, SOC 77%.
   Выполнить один шаг; убедиться в новой ненулевой рассчитанной точке.
6. Ввести 5,3 кВт → «Применить нагрузку» → проверить «ожидает» → «Один шаг».
   Проверить квитанцию времени и отметку на графике, историю первого шага.
7. «Запуск» → «Пауза» → дождаться завершения шага → «Запуск» → «Стоп».
8. Сохранить JSON, CSV и SVG штатно на телефон. Открыть JSON через выбор файла,
   выполнить свежий короткий replay БЕЗ сети. Сохранить диагностику «после».
9. Закрыть и вновь открыть со значка в авиарежиме, проверить сохранённую историю.
10. Отрицательный тест делать только в отдельном тестовом origin/профиле, без
    пользовательской истории: очистить его данные, отключить сеть, открыть.
    Не должно быть ложной готовности или рассчитанного ответа из отсутствующего кэша.
Результаты каждого пункта: выполнен / ошибка / не проверен; приложить скриншоты
и диагностику. До этого не заявлять «Android offline проверен».

ЛОКАЛЬНЫЕ ПРОВЕРКИ РАЗРАБОТЧИКА
Из каталога NIR_app_v1:
python android_validation/build.py --download  (первый раз с интернетом)
python android_validation/build.py             (повторно из локальных ресурсов)
python android_validation/serve.py             (только localhost для QA на ПК)
python -m unittest test_android_adapter -v
python android_validation/parity.py             (сверка сохранённых actual-данных)
python android_validation/ui_parity.py          (скачанный опыт против Python/replay)
python android_validation/final_checks.py       (ресурсы/защищённые файлы/XML)
python -m unittest discover -v                  (полная регрессия, не лёгкий self-test)
probe.html — отдельная QA-страница реального Worker. Полная 60-секундная проверка
выполняется только явной кнопкой; DP не запускается.
Версии/источники/лицензии — runtime-lock.json, asset-manifest.json, licenses/.
